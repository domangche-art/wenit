**에뮬레이터에서 찾아 고친 문제**
1. 트리 순회는 `reel_watch_player` 를 찾지 못했다(접근성상 "중요하지 않은" 뷰). 기존과 같은 ID 검색으로 되돌렸다.
2. 순회 비용이 컸다. YouTube 는 ID 검색만 하도록 바꿨다.
3. 대상 앱 대화상자를 이탈로 처리했다. `OVERLAY` 가림으로 바꿨다.
4. 홈 버튼 뒤 PiP 플레이어(0.077)를 "가림"으로 계속 유지했다. `PLAYER_MINIATURE` 로 이탈 처리하도록 바꿨다.
5. 쇼츠 스크롤 이벤트에 인덱스가 없었다. 이동량 기반 페이지 넘김 판정을 추가했다.

**환경 주의**: 이 AVD 에는 이 서비스가 "접근성 버튼" 단축키로 등록돼 있다. 화면 오른쪽 끝(x≈996)을 탭하면 서비스가 꺼졌다(시스템 로그 `accessibility_button_targets`). 앱 결함은 아니다. 자동화 탭은 오른쪽 끝을 피한다.

- 시나리오 A 의 AI 이유에 `lv1 은 …` 이 나왔다. 앞선 이유가 입력으로 다시 들어가 반복된 것으로 보인다. 프롬프트로는 막히지 않아 저장 전 검증으로 막았다. 검증은 단위 테스트만 했고 이 수정 뒤 AI 를 다시 호출하지는 않았다

- 기기가 잠금 입력을 요구해 사용자에게 해제를 요청했다
- 복원 명령을 사용자가 중단했다. 변수와 상대 경로가 섞인 명령이었다. 경로를 직접 적어 다시 실행했고, 보조 파일이 없어 `rm` 은 쓰지 않았다

### 남은 문제

- 알림 방식은 답하지 않으면 첫 알림만 울리고 그 뒤는 내용만 조용히 바뀐다. 다시 알려 주는 힘은 약해졌다

- 최대 단계 2분 간격은 메모리에만 있어 서비스가 다시 시작되면 사라진다
- 10초가 안 되는 쇼츠 하나만 보고 나가면 복귀가 아니라 "앱만 엶" 으로 남는다
- 10단계에서 남긴 "시간당 최대 120회" 는 최대 단계에서는 시간당 약 30회로 줄었지만, 그 아래 단계는 쿨다운 30초 그대로다
- 시드의 에이전트 이력은 수정 전 시드가 든 기기에서는 표시가 없을 수 있다(10단계와 같음)

### [2] 목표 유형 확장

| 유형 | 기간 | 묶음 | 판정 방법(지금 모으는 데이터만) |
|---|---|---|---|
| WEEKLY_TOTAL | 주간 | 시간 줄이기 | 월~일 추정 시청 합 ≤ N분. 넘으면 즉시 초과, 일요일이 끝나면 달성 |

### 그림 지정 구조

`BadgeArtResolver.resolve(id, tier)` 가 처음 있는 것을 고른다(순수 함수, 단위 테스트).

1. 배지·등급 전용 `badge_<id>_t<0~4>`
2. 배지 전용 `badge_<id>`(13단계 규칙, 등급 구분 없음)
3. 등급 틀 `badge_frame_t<0~4>` + 배지 기호 `badge_symbol_<id>` 합성(기호를 틀의 56% 크기로 가운데 겹침). 둘 다 있어야 한다
4. 공통 `badge_common`(등급 색 고리 안에 둥글게)

요청의 우선순위(전용 → 틀+기호 → 공통)에 13단계에서 만든 "배지 전용" 규칙을 2번으로 넣었다. 1~3은 모양이 등급을 나타내므로 고리를 그리지 않는다. 디자인 팀의 "등급 틀 5장 + 배지 기호 9장"은 3번 이름으로 넣으면 코드 수정 없이 바뀐다. 리소스는 이름으로 찾고(`getIdentifier`), 축소 대비 `res/raw/keep_badges.xml` 이 `badge_*` 를 남긴다.
